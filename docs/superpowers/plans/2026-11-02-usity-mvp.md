# USITY MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** К 15.12.2026 показать работающий сценарий: сообщение в выбранной Telegram-теме → предложения пяти независимых агентов → решение админа → ДЗ или материал в приложении iOS/Android.

**Architecture:** Flutter-приложение обращается к FastAPI; PostgreSQL хранит группы, расписание, задания, предложения и решения, S3-совместимое хранилище — файлы. aiogram принимает события одной Telegram-темы; фоновые задания формируют EventBundle, независимо вызывают пять агентов и создают карточку проверки. На устройстве SQLite хранит опубликованные данные и очередь допустимых offline-действий.

**Tech Stack:** Flutter/Dart, Python/FastAPI, aiogram, PostgreSQL, S3-совместимое хранилище, Redis/очередь, SQLite; заменяемые OCR и LLM провайдеры. Конкретные пакеты, версии и провайдеры фиксировать в первом PR соответствующего модуля после проверки совместимости и доступности.

**Spec:** [MVP](../../product/mvp.md), [пять агентов](../specs/2026-10-31-five-ai-agents-design.md), [GitHub workflow](../../development/github-workflow.md).

## Global Constraints

- До отдельного решения команды это план, а не старт разработки продукта.
- Один пользователь состоит в одной группе; одна группа подключает одну Telegram-тему.
- Пять агентов запускаются независимо, не публикуют данные и сохраняют обоснование/источники.
- Публикация ДЗ и групповых материалов только через решение админа; ДЗ привязано к конкретной паре.
- Реальные чаты, ключи и персональные данные не попадают в Git; учебные примеры синтетические или обезличенные с необходимыми согласиями.
- Каждая задача — отдельная ветка и небольшой PR; один другой участник проверяет изменения до слияния.

## Review Focus

- ДЗ, разделенное на 2–3 сообщения: один EventBundle, один черновик с ID всех источников (задачи 3–4).
- Сообщение из соседней темы: не попадает в обработку (задача 3).
- Несколько админов подтверждают один черновик: одно решение и одна публикация (задача 6).
- ДЗ для подгруппы или четной недели: показывается только подходящим студентам под нужной парой (задачи 2, 7).
- Выполнение offline перед изменением версии ДЗ админом: новая версия остается невыполненной (задача 8).

## Границы и структура репозитория

Предлагаемые каталоги закрепить в Issue #1 до первого кода: `backend/app/{auth,groups,schedule,assignments,materials,review,agents,integrations,notifications,sync}/`, `backend/tests/`, `mobile/lib/{features,core}/`, `mobile/test/`, `docs/`. Контракты API и пять интерфейсов агентов принадлежат backend; мобильный клиент не вызывает LLM напрямую. PR не должен одновременно менять несвязанные backend и Flutter модули.
