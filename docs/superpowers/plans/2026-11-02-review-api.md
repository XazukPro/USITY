# Review API Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans; выполнять шаги с тестами до реализации.

**Goal:** проверяемый сценарий агент Антона → сохраненный черновик → админское решение → ДЗ у конкретной пары.

**Architecture:** FastAPI, синхронный SQLAlchemy 2, PostgreSQL как основная БД; SQLite для быстрых тестов и локального стенда. Публикация и решение в одной транзакции, compare-and-set статуса черновика. Агент вызывается внутренней функцией, без публичного endpoint публикации от AI.

**Tech Stack:** Python 3.14, FastAPI, SQLAlchemy, psycopg, pytest. Версии фиксируются после установки.

**Spec:** `docs/product/mvp.md`, `docs/research/ai-course-notes-ru.md`; существующий прототип `backend/app/agents/homework.py`.

## Global Constraints

- Только админ/owner своей группы публикует ДЗ; студент не видит исходный чат и чужое выполнение.
- ДЗ требует конкретного будущего занятия. Агент лишь предлагает текст.
- Сохранять контекст, ответ модели, версии и человеческий результат; Git содержит только синтетику.
- Не вводить неутвержденную общую схему агентов вместо контракта прототипа.

## Review Focus

- Два одновременных решения → один победитель, одна публикация.
- Чужая группа/роль из запроса → отказ; роль берется из БД.
- Неверная Telegram-тема → отказ до обращения к модели.
- Сбой модели/повтор события → отсутствие частичной публикации/дубля.
- Прошедшая пара/устаревшая версия выполнения → отказ без потери черновика.

## Решения реализации

Продолжаем в существующем checkout на отдельной ветке. Email OTP еще не реализован: локальный CLI выдает случайные временные bearer-сессии, хеш хранится в БД. API не принимает user_id/role от клиента. Этот этап не готов для публичного размещения: нет onboarding, подгрупп, расписания семестра, push и миграций существующих БД. Для пустой тестовой БД используется явная команда создания схемы.

## Журнал выполнения

02.11: исходные 8 тестов агента прошли. Новые API/ingestion тесты сначала упали на отсутствующих модулях, затем прошли. PostgreSQL 17 запущен в отдельном временном контейнере. Добавлены проверки одновременных решений, идемпотентности событий, отката публикации и отдельного выполнения.

Ревью выявило гонки SQLite и отсутствие текущего результата в ответе 409. Три регрессионных сценария воспроизвели проблемы. SQLite использует BEGIN IMMEDIATE для атомарности; PostgreSQL сохраняет блокировки строк. Цена: локальная SQLite сериализует транзакции. 409 теперь содержит текущее решение.

Изолируем работу веткой существующего checkout; новая рабочая копия не требовалась. API и команда демо не публикуются наружу. Общие продуктовые правила не менялись.

Повторная проверка ревью: текущий статус должен возвращаться и после начала пары. CAS черновика перенесен перед проверкой пары, все изменения откатываются при невалидном занятии. Регрессионный тест сначала упал (422 вместо 409), после исправления прошел. Добавлен GET /me для серверных прав клиента.
