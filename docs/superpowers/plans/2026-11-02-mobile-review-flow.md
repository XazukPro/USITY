# Mobile review flow implementation plan

> **For agentic workers:** Use superpowers:executing-plans, тесты перед реализацией.

**Goal:** показать в Android реальный сценарий API: проверка черновика → ДЗ в паре → личное выполнение.

**Architecture:** Flutter HTTP repository получает /me, пары, ДЗ. Страница расписания использует существующие карточки. Админская очередь открывается отдельным экраном, редактирует plain text и выбирает конкретную будущую пару. Сервер проверяет все права. Временная сессия задается только для debug-сборки через локальный .env.* JSON с dart-define-from-file. Release не использует демонстрационные ключи.

**Tech Stack:** Flutter/Dart, package:http, FastAPI из PR #18.

**Spec:** docs/product/mvp.md.

## Ограничения и решения

Не реализуем email-login фиктивной формой. До его разработки это явно помеченный учебный стенд. Без debug-конфигурации сохраняется визуальный пример расписания. Основной API работает только на loopback; Android использует adb reverse. Светлая/темная тема остается прежней. Остальные вкладки пока заглушки; offline и архив не заявляются.

## Шаги
