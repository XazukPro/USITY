# Пользовательские сценарии и права

Раздел описывает целевое поведение MVP. Текущее состояние реализации приведено в [файле статуса](08-статус-и-метрики.md).

## Создание и вступление

1. Пользователь вводит email и подтверждает вход одноразовым кодом.
2. Создатель задаёт название группы, даты семестра, предметы, доступные типы занятий и количество подгрупп по каждому предмету.
3. Для каждой пары указываются предмет, день недели, время, преподаватель, аудитория или ссылка, тип занятия, подгруппа и периодичность.
4. Владелец получает приглашение, передаёт его студентам и подключает одну тему Telegram.
5. Студент открывает приглашение, входит в аккаунт и выбирает по одной подгруппе на предмет. Если он пропускает выбор, часть занятий может быть скрыта.

Приглашение из текущего прототипа использует ссылку `usity://` для установленного приложения. Для публичного запуска необходимо определить домен и поведение ссылки при отсутствии установленного приложения.

## Права внутри группы

| Действие | Владелец | Администратор | Студент |
| --- | --- | --- | --- |
| Назначить или снять администратора | Да | Нет | Нет |
| Передать владение и удалить группу | Да | Нет | Нет |
| Подключить, отключить или переподключить тему | Да | Нет | Нет |
| Менять расписание, предметы и подгруппы | Да | Да | Нет |
| Проверять и публиковать групповое ДЗ | Да | Да | Нет |
| Выбрать собственные подгруппы и выполнить ДЗ | Да | Да | Да |
| Управлять своими личными задачами и файлами | Да | Да | Да |
| Предложить материал группе | Да | Да | Да, с проверкой админом |

Удаление лишнего участника выполняется администрацией группы. Граница назначения администраторов остаётся за владельцем.

## ДЗ от сообщения до результата

Сообщение «По математике задания 1–5» и следующее «сдать к понедельнику, условия на фото» рассматриваются как возможные части одного события. Администратор видит оба источника, OCR фото и предложения по предмету, паре и аудитории. Он может исправить текст и распознанный текст, выбрать одну или несколько подгрупп, затем подтвердить или отклонить предложение.

Если найденный срок уже прошёл, публикация требует выбора новой пары. Если администраторы одновременно рассматривают карточку, применяется первое решение. Остальные получают актуальное состояние. Если информация не относится к учебной задаче или материалу, она может быть отклонена.

При создании ДЗ вручную админ начинает с карточки конкретной пары. Приложение подставляет доступные параметры занятия. Содержание можно отредактировать перед публикацией.

## Завершение и восстановление

Отметка группового ДЗ принадлежит конкретному студенту. Админ видит содержание и состояние публикации, но не индивидуальную статистику выполнения. Пункт ДЗ после выполнения отображается зачёркнутым внутри пары и в задачах. Нажатие позволяет восстановить его.

Личная задача появляется в календарной оси при заданном времени. После завершения она исчезает с оси, остаётся зачёркнутой в списке три дня и доступна для восстановления. Задачи без времени остаются в разделе «Задачи». При перемещении пользователь может допустить пересечение с парой.

## Группа и семестр

При удалении группы владелец видит состояние восстановления в течение семи дней. У студентов группа скрывается сразу. Восстановление возвращает участников и данные. Перед удалением собственного аккаунта владелец передаёт права. Настройки расписания могут меняться в течение семестра, а следующий семестр создаётся отдельно.

Предмет существует на уровне группы и может сохранять учебные материалы после завершения семестра. Старые ДЗ скрываются и технически хранятся 30 дней, далее применяются согласованные правила удаления или обезличивания.
