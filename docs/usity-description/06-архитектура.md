# Архитектура и данные

```text
Учебная тема Telegram
       ↓  текст, подписи, фото и файлы
Бот aiogram → входящие события и фоновый обработчик
       ↓
OCR фото → контекст события → пять AI-агентов
       ↓                       ↓
PostgreSQL ← черновик ← очередь проверки администратора
       ↓ после решения
FastAPI ↔ Flutter iOS / Android ↔ SQLite устройства
       ↕
Приватное S3-хранилище материалов
```

Это целевая схема MVP. Текущий бот принимает текст и вызывает поиск ДЗ. Единый запуск пяти агентов и обработка фото требуют интеграции.

## Сервер

FastAPI предоставляет клиентам доступ к аккаунту, группе, расписанию, заданиям и материалам. Доступ определяется серверной сессией и членством. Админские операции проверяют роль. PostgreSQL хранит пользователей, группы, расписание, версии заданий и личное выполнение, материалы и решения проверки. Миграции обновляют схему по версиям. SQLite применяется для локальной разработки и тестов.

Для файлов используется приватное S3-совместимое хранилище. В локальном стенде используется закрытая папка. Сервер проверяет права и отдаёт файл авторизованному клиенту. Планируются фоновый обработчик, повторные попытки и мониторинг. При необходимости Redis может использоваться для очереди.

## Мобильный клиент

Flutter обеспечивает общую кодовую базу iOS и Android. Сессия хранится в защищённом хранилище устройства. SQLite содержит локальное расписание и очередь изменений. Идентификаторы операций и версии помогают повторять запросы после сбоя. Для личных задач при несовместимых изменениях предлагается выбор версии, обновление админа по ДЗ имеет приоритет.

## Основные сущности

- Пользователь, сессия, группа, членство и роль, приглашение.
- Семестр, предмет, предметная подгруппа, выбор студента, занятие и разовое изменение.
- Задание, версия, личная отметка выполнения, личная задача.
- Материал, категория, связь с предметом и заданием.
- Telegram-подключение, сообщение, входящее событие, результат агента, черновик и решение админа.
- Настройки уведомлений, устройство, токен push и технические события.

Часть сущностей ещё требуется добавить или расширить при объединении веток. Схема хранения не является обещанием наличия отдельной таблицы для каждого понятия.
