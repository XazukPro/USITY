# Тестирование и приёмка MVP

## Сквозные сценарии

| Сценарий | Ожидаемый результат |
| --- | --- |
| Вход и приглашение | Новый студент входит по коду, принимает ссылку и попадает в одну группу |
| Подгруппы | Английский и информатика используют независимый выбор, чужие пары и ДЗ недоступны |
| ДЗ из двух сообщений | Оба сообщения входят в контекст, админ проверяет предложение, ДЗ появляется у конкретной пары |
| Соседняя тема | Сообщение не записывается как источник и не отправляется в AI |
| Спорная подгруппа | Черновик остаётся на проверке, админ может выбрать несколько подгрупп |
| Повтор Telegram-события | Дополнительное ДЗ не создаётся |
| Одновременная проверка | Одно решение применяется, другой админ получает актуальный статус |
| Перенос или отмена | Меняется нужное ДЗ после решения админа, затронутые студенты получают предусмотренное уведомление |
| Личное выполнение | Статус одного студента не влияет на другого и не раскрывается администратору |
| Материал | Админ публикует файл, предложение студента проходит проверку, права на скачивание соблюдаются |
| Offline | Задача и отметка переживают перезапуск и отправляются после восстановления соединения |
| Конфликт устройств | Пользователь выбирает версию личной задачи, новая версия группового ДЗ снова отображается |
| Восстановление группы | После удаления и восстановления возвращаются участники и данные в пределах семидневного срока |

## Уровни проверки

- Модульные тесты проверяют правила сроков, подгрупп, форматов и результатов агентов.
- API-тесты проверяют роли, изоляцию групп, миграции, конкуренцию и повторные запросы на SQLite и PostgreSQL.
- Flutter-тесты проверяют отображение, сохранение и синхронизацию. Скриншоты сравниваются с эталонами светлой и тёмной темы.
- Сквозные проверки проходят на Android Emulator и iOS Simulator, затем на физических iPhone и Android с сетью, без сети и после перезапуска.
- Пилот с добровольной группой проверяет понятность сценариев и качество предложений модели.

## Метрики

Показатели и методика описаны в [статусе и метриках](08-статус-и-метрики.md). Для полноты обнаружения требуется размечать все реальные ДЗ в выбранных эпизодах, включая те, которые модель пропустила. Задержку измеряют от последнего относящегося сообщения до появления карточки администратору. Для надёжности публикации проверяются группа, подгруппа, пара, отсутствие дублей и индивидуальные отметки.

Для каждого запуска фиксируются дата, версия клиента и сервера, версия модели/промпта, окружение, размер выборки, результаты и известные ошибки. Данные для демонстрации и автоматических тестов синтетические.
