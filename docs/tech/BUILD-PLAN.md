# План разработки

Стек подтверждён: Flutter/Dart, Python/FastAPI, aiogram, PostgreSQL, S3-совместимое хранилище, Redis/очередь и SQLite для offline. Существующие `mobile/` и `backend/` продолжаются; дублировать их нельзя. На каждом этапе: отдельная ветка, понятный набор изменений, скриншоты экранов в светлой и тёмной теме рядом с эталонами из `docs/design/screens/`, закрытые критерии приёмки. Этап начинается только по отдельной задаче.

## Этап 0. Основа
- Сверить существующий Flutter-проект с дизайн-системой; настроить форматирование, анализатор и тесты Dart.
- Модуль `theme/tokens` из `docs/design/tokens.json`, переключение светлая/тёмная/системная, шрифты Onest и JetBrains Mono.
- Каркас навигации: 4 вкладки по макету, панель вкладок со счётчиком.
- Экран-галерея компонентов (только в режиме разработки).
- Приёмка: галерея показывает каждый компонент из `DESIGN-SYSTEM.md` в обеих темах, нет литералов цвета вне `theme/tokens`; существующая интеграция с API не сломана.

## Этап 1. Расписание на заглушках
- Компоненты: `DayStrip`, `TimelineRow`, `TimelineTask` (одиночная и пересекающиеся), `HwMark`, `WeekRow`, `HomeworkRow`, `RingCheck`, `Fab`, `BottomSheet`, `Chip`, `SegmentedControl`.
- Экраны: «День» (ось с парами и личными задачами), «Неделя», открытая пара (с ДЗ), «Новая задача».
- Логика: `formatGap`, определение текущей пары, группировка по дням, отметка выполнения на заглушке.
- Приёмка: совпадение с эталонами экранов 1–4, модульные тесты на `formatGap`, группировку пересечений (капсулы и подпись «Задачи пересекаются»), перенос личной задачи удержанием с шагом 5 минут, пометку «ДЗ · N» (считает невыполненные пункты) и разделение ДЗ/личных задач. Пары остаются неподвижными для студента.

## Этап 2. Задачи, Материалы, Настройки
- Экраны 5–7 (вкладка «Задачи»: единый список ДЗ и личных задач с фильтром «ДЗ / Всё / Задачи», «Материалы», «Настройки»), выбор темы.
- Приёмка: совпадение с эталонами, отметка личной задачи синхронна между «Днём», «Неделей» и вкладкой «Задачи»; выполненная исчезает с оси, остаётся зачёркнутой в списке 3 дня и восстанавливается. Отметка ДЗ синхронна между открытой парой, вкладкой «Задачи» и пометкой «ДЗ · N»; выполненное ДЗ остаётся зачёркнутым в списке без трёхдневного правила.

## Этап 3. Онбординг старосты
- Экраны 9–13 и формы добавления предмета и пары.
- Приёмка: после «Готово» на заглушках видно собранное расписание.

## Этап 4. Бэкенд и вход
- Продолжить существующий FastAPI: email-код, модель данных из `ARCHITECTURE.md`, owner/admin/student, подгруппы по предметам, приглашение по ссылке, материалы и базовый SQLite offline в приложении. Миграции вместо создания схемы учебным скриптом.
- Приёмка: студент видит только свою группу, предметные подгруппы и свои личные задачи; тесты доступа к черновикам, публикации ДЗ для нескольких подгрупп и восстановления offline-действий.

## Этап 5. Telegram и черновики
- Бот на aiogram, подключение одной темы по коду, хранение только относящихся сообщений, минимум пять независимых AI-агентов, экран «Проверка ДЗ» (экран 8) и ручное ДЗ админа из карточки пары.
- Приёмка: сообщение в теме превращается в черновик, админ подтверждает, ДЗ появляется у нужных студентов в нужной паре; сообщения других тем не поступают в AI или базу.

## Этап 6. Уведомления и завершение MVP
- Push по `docs/product/mvp.md`: новое/перенесённое/отменённое ДЗ, напоминание за 24 часа, выходная сводка, значимые изменения расписания, события админа; личные напоминания настраиваются отдельно. Проверить offline, материалы и полный сценарий на iOS/Android.
- Приёмка: правила адресатов и частоты push подтверждены тестами, сквозной сценарий работает на устройствах; дополнительные виджеты отложены на период после MVP.
