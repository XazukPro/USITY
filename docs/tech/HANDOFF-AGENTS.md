# AGENTS.md — USITY

Ты разрабатываешь мобильное приложение **USITY** (iOS + Android, один дизайн, светлая и тёмная темы). Это приложение для студенческой группы: расписание, домашние задания (ДЗ) и материалы в одном месте. Читай этот файл первым, затем документы из раздела «Где что лежит».

## Что делает приложение

Староста создаёт группу, вносит предметы, подгруппы и расписание на семестр, подключает к группе одну тему Telegram-чата и приглашает студентов по ссылке. Telegram-бот читает только эту тему. AI-агент превращает сообщения в **черновики** ДЗ и материалов. Староста проверяет черновик: подтверждает, исправляет или отклоняет. Только подтверждённое ДЗ показывается студентам, и только внутри открытой пары, к которой оно относится, с учётом подгруппы; на оси времени дня у такой пары стоит пометка «ДЗ · N». Отдельно от ДЗ есть **личные задачи**: их создаёт сам студент, они стоят на оси времени (с пересечениями). Во вкладке «Задачи» ДЗ и личные задачи собраны в один список с переключателем «ДЗ / Всё / Задачи». Выполнение задач у каждого студента личное: выполненное пропадает из расписания только у него.

## Где что лежит

- `docs/product/PRODUCT-RULES.md` — роли, жизненный цикл ДЗ, подгруппы, личное состояние. Правила продукта важнее любых предположений.
- `docs/design/SCREENS.md` — спецификация каждого экрана: структура, размеры, данные, состояния, переходы.
- `docs/design/DESIGN-SYSTEM.md` — токены, компоненты, правила оформления.
- `docs/design/tokens.json` — единственный источник значений цвета, радиусов, отступов и шрифтов.
- `docs/design/screens/*.png` — эталонные картинки экранов (светлая и тёмная темы). Шрифт на картинках заменён системным; настоящий шрифт — Onest.
- `docs/design/prototype/*.html` — те же экраны в HTML с точными значениями CSS. Открывай, когда нужен точный размер, отступ или цвет.
- `docs/tech/ARCHITECTURE.md` — предлагаемый стек, модель данных, конвейер Telegram → AI → проверка.
- `docs/tech/BUILD-PLAN.md` — порядок работы по этапам и критерии приёмки.

## Жёсткие правила дизайна

1. Не придумывай интерфейс. Каждый экран делай по `SCREENS.md` и сверяй с картинкой из `docs/design/screens/`. Если экрана или состояния в документах нет, задай вопрос, а не рисуй по своему вкусу.
2. Никаких «сырых» значений в коде экранов. Цвета, радиусы, отступы, размеры шрифта берутся из модуля токенов `theme/tokens`, который генерируется из `docs/design/tokens.json`. Запрещены литералы вроде `#CFC8FB` или `borderRadius: 14` вне этого модуля.
3. Обе темы обязательны. Любой компонент проверяется в светлой и тёмной теме.
4. Стиль: воздушный, спокойный, пастельный. Скругления крупные, рамок почти нет, лишней информации нет. Не добавляй тени, градиенты, иконки и подписи, которых нет в макете.
5. Тип пары задаёт цвет: семинар розовый, лекция зелёный, лабораторная голубой. Цвет всегда сопровождается иконкой (семинар: users, лекция: presentation/monitor, лабораторная: flask). Только цветом информацию не передавать.
6. В информации о паре показываются: название предмета, время, ФИО преподавателя (без иконки рядом), аудитория или «Онлайн», подгруппа (в строке преподавателя), пометка «ДЗ · N». Сами задания ДЗ показываются только внутри открытой пары. **Названия учебных групп не показывать нигде.**
7. Перемены не подписываются. Между парами выводится только промежуток времени в формате «10мин.», «1ч. 20мин.» (см. `SCREENS.md`).
8. Шрифты: Onest для интерфейса, JetBrains Mono для времени и аудиторий. Веса 400, 500, 600.
9. Флажки выполнения везде стоят справа от текста (и у ДЗ, и у личных задач). Минимальная область нажатия 44×44 pt. Все интерактивные элементы имеют подпись для скринридера. Контраст текста не ниже 4,5:1 (уже проверен для всех пар токенов; новые пары проверяй).
10. Язык интерфейса: русский. Все строки лежат в одном файле локализации, не в разметке.

## Жёсткие правила продукта

- Вид «Дня» один: левая ось времени с парами и личными задачами. Карточного вида нет и не нужен.
- **ДЗ и личная задача — разные сущности**, в коде и в интерфейсе их не смешивать: у ДЗ квадратный флажок, у личной задачи круглый; в модели данных они в разных таблицах (`HomeworkItem` и `PersonalTask`).

- Черновик ДЗ никогда не виден студентам.
- ДЗ привязано к конкретной паре и подгруппе; если подгруппа не указана в исходном сообщении, это спорное место для старосты, а не догадка агента.
- Отметка «выполнено» хранится на пользователя. Она не меняет ДЗ для остальных.
- Раздел «Проверка ДЗ» виден только старосте и находится в «Настройках»; на иконке «Настройки» в панели вкладок показывается число непроверенных черновиков.
- Бот читает только одну подключённую тему. Сообщения из других тем не сохраняются.

## Как работать

- Двигайся этапами из `docs/tech/BUILD-PLAN.md`. Один этап: одна ветка, один понятный набор изменений, закрытые критерии приёмки.
- Сначала готовые данные-заглушки (mock) и экран, потом бэкенд. Интерфейс должен совпасть с эталоном до подключения реальных данных.
- После каждого экрана запусти приложение, сними скриншот в обеих темах и сравни с `docs/design/screens/`. Перечисли расхождения в описании изменений.
- Тесты: чистая логика (формат промежутка, подгруппы, видимость ДЗ, состояния задач) покрывай модульными тестами. Для компонентов делай снимки в обеих темах.
- Не меняй токены и макеты молча. Нужно изменение дизайна — предложи правку в `docs/design/` отдельным коммитом и объясни, зачем.
