# Архитектура USITY

Стек ниже выбран для проекта. Оригинальное предложение handoff сохранено в истории импорта; новые модули продолжают существующие Flutter и FastAPI, не создавая второй клиент и сервер.

## Стек

- **Мобильное приложение**: Flutter/Dart, общий код для iOS и Android; обе темы и шрифты Onest/JetBrains Mono по `docs/design/tokens.json`. SQLite для базового offline; безопасное хранение сессии и push-провайдер выбираются при реализации.
- **Бэкенд**: Python/FastAPI, PostgreSQL; проверка роли и принадлежности группы на сервере. S3-совместимое хранилище для файлов; Redis с очередью фоновых задач для OCR/LLM.
- **Telegram-бот**: отдельный сервис на Python/aiogram. Читает только одну подключённую тему группы, группирует относящиеся сообщения и передаёт кандидатов в очередь.
- **AI**: минимум пять независимых специализированных агентов по общему контракту из `docs/superpowers/specs/2026-10-31-five-ai-agents-design.md`. Агенты возвращают предложения; публикация и изменение группового ДЗ требуют решения админа. Модели и ключи доступны только на сервере.
- **Уведомления**: push согласно `docs/product/mvp.md`. Виджеты домашнего экрана после MVP.

## Модель данных

| Сущность | Поля |
|---|---|
| `User` | id, имя, аватар, telegram_id (необязательно) |
| `Group` | id, название, начало и конец семестра, чередование недель, invite_code |
| `Membership` | user_id, group_id, role (`owner` / `admin` / `student`) |
| `Subject` | id, group_id, название |
| `Subgroup` | id, subject_id, название; подгруппа всегда принадлежит предмету |
| `StudentSubjectGroupChoice` | user_id, subject_id, subgroup_id; один выбор на предмет |
| `Lesson` | id, group_id, subject_id, kind (`lecture` / `seminar` / `lab`), weekday, start, end, week_parity (`all` / `even` / `odd`), teacher_name, room (текст или `online`), subgroup_id (необязательно) |
| `LessonOccurrence` | вычисляется из `Lesson` и семестра: дата + урок; исключения (отмена, перенос) хранятся отдельно |
| `TelegramLink` | group_id, chat_id, topic_id, статус, код подключения |
| `SourceMessage` | id, group_id, автор, текст, время, вложения |
| `Draft` | id, group_id, тип (`homework` / `material`), статус (`pending` / `confirmed` / `rejected`), лист исходных сообщений, предложенные предмет, пара (`lesson_id` + дата), подгруппа, задачи, материалы, список спорных мест |
| `Homework` | id, group_id, lesson_id, дата пары, версия, создан из draft_id; видимость — всем или набору подгрупп предмета |
| `HomeworkSubgroup` | homework_id, subgroup_id; пустой набор означает видимость всему предмету |
| `HomeworkItem` | id, homework_id, текст, порядок, вложения (пункт ДЗ) |
| `HomeworkCompletion` | user_id, item_id, completed_at (строка есть = выполнено) |
| `PersonalTask` | id, user_id, название, начало и длительность (необязательно), напоминание, completed_at, version; время кратно 5 минутам |
| `Material` | id, group_id, subject_id, lesson_id (необязательно), заголовок, тип (`file` / `link` / `photo`), url, размер, источник |

## Правила, которые нужно закрепить в коде и тестах

- Студент видит только `Homework` и `Material` со статусом «подтверждено» из своей группы, относящиеся ко всей группе или к его подгруппе.
- `Draft` в статусе `pending` или `rejected` невидим студентам на уровне доступа к данным, а не только на уровне интерфейса.
- `HomeworkCompletion` принадлежит пользователю. Пометка «ДЗ · N» на паре считает невыполненные пункты ДЗ этого пользователя и исчезает, когда их нет.
- Вкладка «Задачи» строится запросом, объединяющим `HomeworkItem` (с пометкой типа «ДЗ», с `lesson_id` и временем пары) и `PersonalTask` владельца; фильтр «ДЗ / Всё / Задачи» применяется на клиенте.
- `PersonalTask` видна только владельцу. Пересечение по времени (с другими личными задачами и с парами) не запрещается, а показывается интерфейсом; его считает клиент по данным дня.
- Завершённая личная задача исчезает с оси и остаётся зачёркнутой в списке 3 дня; завершённый пункт ДЗ остаётся внутри пары и в списке до изменения/окончания жизненного цикла ДЗ.
- Изменение подтверждённого ДЗ приходит новым черновиком; при подтверждении создаётся новая версия, студентам, уже отметившим задачу, показывается пометка «изменено».
- Промежуток считается между соседними элементами оси дня этого пользователя (пары с учётом подгруппы и личные задачи со временем), в формате `formatGap`.

## Схема JSON ответа AI-агента

```json
{
  "kind": "homework",
  "subject_guess": "Дискретная математика",
  "lesson_guess": {"date": "2026-11-06", "start": "08:30"},
  "subgroup_guess": null,
  "tasks": [{"text": "Решить №4.12–4.18"}, {"text": "Подготовить доказательство теоремы 3"}],
  "materials": [],
  "uncertain": [{"field": "subgroup", "reason": "Не указана подгруппа"}],
  "source_message_ids": ["m1", "m2"]
}
```

Любое поле, в котором агент не уверен, попадает в `uncertain`, а не заполняется догадкой.

## Безопасность

Приглашение по ссылке создаёт `Membership` со студенческой ролью; код можно сменить. Токен бота, ключи AI и сервисные ключи хранятся только на сервере. Бот игнорирует всё, кроме подключённой темы.
