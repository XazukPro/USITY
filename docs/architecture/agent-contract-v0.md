# Контракт пяти агентов — проект v0.1

Этот документ адресован всем пяти разработчикам. Цель — позволить агентам разрабатываться отдельно и объединяться без зависимости друг от друга. Обсуждение и утверждение: [Issue #1](https://github.com/XazukPro/USITY/issues/1). До утверждения это **предложение**, а не миграция существующего прототипа Антона.

## EventBundle

Backend создает один пакет для одного события выбранной Telegram-темы. Все ID передаются строками, даже если Telegram использует числа. Время — ISO 8601 с часовым поясом. `event_id` стабилен для повторной обработки; порядок сообщений сохраняется.

```json
{
  "schema_version": "0.1",
  "event_id": "evt-demo-1",
  "group_id": "group-demo-1",
  "source": {"platform": "telegram", "chat_id": "-100123", "topic_id": "42"},
  "messages": [
    {"id": "101", "sent_at": "2026-11-02T09:00:00+03:00", "text": "По математике к понедельнику:", "attachments": []},
    {"id": "102", "sent_at": "2026-11-02T09:01:00+03:00", "text": "решить номера 4 и 5", "attachments": []}
  ],
  "context": {
    "subjects": [{"id": "subject-math", "name": "Математика", "subgroup_ids": []}],
    "upcoming_lessons": [],
    "active_assignments": []
  }
}
```

Вложения: `id`, `kind` (`photo`/`file`/`link`), `mime_type`, безопасная ссылка на сохраненный объект при необходимости, `ocr_text` только для фото. Не вкладывать ключи доступа или чужие сообщения. Каждый агент получает минимально нужную часть `context`; список предметов и пар нужен агенту расписания, действующие ДЗ — агентам дублей и изменений. Для standalone-теста можно подать синтетический пакет напрямую.

## Результат запуска

Вызов каждого агента возвращает `AgentRunResult`: `schema_version`, `event_id`, `agent_id`, `proposals` (массив, в том числе пустой), `model_version`, `prompt_version`. Сбой вызова фиксируется отдельно, **не** превращается в `proposals=[]`. Несколько предложений допустимы, если в пакете несколько независимых ДЗ/материалов.

Каждый `AgentProposal` содержит `kind`, `source_message_ids` (непустой массив существующих ID), `uncertain` (boolean), `reason` (краткое объяснение админу) и `fields` с данными своего типа. Запрещено выдумывать source ID или включать сведения другой группы. Валидация сервера отклоняет неизвестный `kind`, пустой источник и несовпадение `event_id`.

| `agent_id` | Допустимый `kind` | `fields` |
| --- | --- | --- |
| `homework_detection` | `new_homework` | `text` — одно plain text поле; не назначать предмет и срок |
| `schedule_matching` | `schedule_match` | `subject_id`, `lesson_occurrence_id`, `subgroup_ids`, `due_at`; неизвестное = `null`/пустой массив с `uncertain=true` |
| `duplicate_check` | `possible_duplicate` или `contradiction` | `assignment_ids`, объяснение различий |
| `material_classification` | `material` | `material_id`/ссылка на источник, `subject_ids`, `category`, `assignment_ids` |
| `assignment_change` | `assignment_update` или `assignment_cancel` | `assignment_id`, предложенное изменение |

Пример выхода агента Антона:

```json
{
  "schema_version": "0.1",
  "event_id": "evt-demo-1",
  "agent_id": "homework_detection",
  "model_version": "provider/model/version",
  "prompt_version": "homework-v1",
  "proposals": [{
    "kind": "new_homework",
    "source_message_ids": ["101", "102"],
    "uncertain": false,
    "reason": "Задание сформулировано в двух соседних сообщениях",
    "fields": {"text": "Решить номера 4 и 5"}
  }]
}
```

`model_version` и `prompt_version` записывает вызывающий код, а не придумывает LLM. Сырой ответ модели хранится отдельно от проверенного результата и решения админа. Предложения агентов объединяются по источникам в ReviewEvent; расхождения сохраняются для человека.

## Обязательные проверки каждого агента

1. Автономный запуск на синтетическом EventBundle без остальных агентов.
2. Валидный выход по схеме или явно зарегистрированная ошибка; таймаут одного агента не блокирует остальных.
3. Источники ответа входят в пакет; неизвестное значение не превращается в догадку без отметки неопределенности.
4. Русскоязычные положительные, отрицательные и спорные примеры; измерение своей метрики на фиксированном наборе.
5. Никаких прямых операций публикации/изменения групповых данных и выполнения инструкций из Telegram-сообщений.
