# USITY для iOS и Android

### Вход по email и расписание группы

После входа откройте расписание. Кнопка «+» создаёт личную задачу. Запланированные
задачи видны рядом с парами, задачи без времени доступны во вкладке «Задачи».
Личные задачи и отметки ДЗ сохраняются в SQLite. При возвращении сети USITY
повторяет отправку, а в настройках есть ручная синхронизация. При одновременной
правке задачи на двух устройствах можно сравнить обе версии и выбрать нужную.
Для офлайн-входа сначала откройте расписание с подключением к API.

Вкладка «Материалы» поддерживает личные и групповые файлы и ссылки. Староста
проверяет предложения студентов перед публикацией для группы. Из карточки пары
можно открыть каталог по её предмету. Открытые ранее файлы доступны офлайн.

Для локальной проверки из корня репозитория активируйте Python-окружение
с зависимостями backend и запустите:

```bash
state_dir=$(mktemp -d)
python backend/local_access.py "$state_dir"
```

Стенд принимает адреса вида `student@example.test`. Тестовые письма появляются
в `$state_dir/<email>.txt`. API слушает только loopback. Во втором терминале:

```bash
adb reverse tcp:8074 tcp:8074
cd mobile
flutter run -d emulator-5554 --dart-define=USITY_API_URL=http://127.0.0.1:8074
```

Для iOS Simulator выберите его ID вместо `emulator-5554` и пропустите команду
`adb reverse`. Создайте группу после входа. В профиле старосты скопируйте
приглашение и откройте его на устройстве второго студента с установленным USITY.
Ссылку также можно вставить на экране вступления. Студент выбирает подгруппы
и открывает расписание. Производственный API требует HTTPS и настроенную почту.
Без параметра сервера доступен отдельный локальный деморежим.

Этап 3. В учебной сессии откройте «Настройки» → «Демо старосты». Введите название группы и даты семестра, добавьте предметы, виды занятий и подгруппы, затем пары на выбранные дни недели. Первый календарный учебный интервал заканчивается в воскресенье недели начала семестра и считается нечётным. С понедельника чётность меняется. Оба конца семестра входят в расписание.

Шаг Telegram позволяет опробовать локальное подтверждение или пропустить подключение. Команда и ссылка на домене `usity.example` демонстрационные. «Поделиться» открывает системное меню устройства. Кнопка «Готово» открывает ближайший учебный день с введёнными парами. Выход из демо старосты возвращает предыдущий профиль студента. Данные новой группы хранятся в памяти этой демосессии.

Пять шагов мастера на Android представлены в [светлой и тёмной темах](docs/stage3). Название предмета и аудитория на снимках введены вручную в ходе проверки.

Этап 2 добавляет три вкладки в учебную сессию. Во вкладке «Задачи» можно переключать ДЗ и личные задачи, открыть пару и изменить выполнение. При отметке выполненной личной задачи она скрывается с оси и остаётся доступной для восстановления в списке до трёх суток с момента отметки. ДЗ остаётся в списке пары.

Во вкладке «Материалы» работают поиск и фильтр по предметам. Одни и те же материалы доступны из пары и каталога. Учебный PDF входит в сборку и открывается в системном просмотрщике, заметки читаются внутри USITY, а ссылка на учебник Python открывается в браузере. В настройках демостудента выбор подгруппы применяется к расписанию и ДЗ по соответствующему предмету. Тема и предпочтение уведомлений сохраняются на устройстве. Отправка push относится к следующим этапам.

Для визуальной приёмки доступны [три экрана в обеих темах](docs/stage2). Показывается профиль студента. В режиме API администратор может перейти в существующую очередь проверки из настроек.

Этап 1. В деморежиме приложение открывает план на сегодня. В представлениях «День» и «Неделя» пары и личные задачи идут по времени. Нажатие на месяц открывает календарь, на пару — её ДЗ и материалы. Квадратный флажок меняет выполнение одного пункта ДЗ и счётчик пары. Круглый флажок снимает личную задачу с оси.

Кнопка «+» открывает редактор задачи. Удерживайте задачу и двигайте вдоль оси: подсказка показывает новый интервал с шагом 5 минут. Нажатие на задачу открывает точный выбор даты и времени. Задачу без времени можно найти и запланировать во вкладке «Задачи».

Состояние учебного расписания живёт в памяти до перезапуска приложения. Переключатель напоминания сохраняет настройку в демонстрационной задаче. Доставка уведомлений, постоянное хранение и подключение новых экранов к серверу относятся к следующим этапам. Для просмотра по окончании каждого этапа запустите обновлённую сборку в видимом эмуляторе и оставьте её на экране соответствующей функции.

Контрольные снимки деморежима в обеих темах находятся в [docs/stage1](docs/stage1). В демо карточка пары открывает учебную текстовую заметку, а форма новой задачи дополнительно поддерживает вариант «Без времени». Время, дата и признаки текущей пары зависят от устройства.

Цвета, базовые отступы, радиусы и типографика генерируются из `../docs/design/tokens.json` командой `python3 tool/generate_tokens.py` из каталога `mobile` при доступном в PATH Dart SDK. Onest и JetBrains Mono входят в сборку с лицензиями OFL. Источник шрифтов — репозиторий google/fonts, каталоги ofl/onest и ofl/jetbrainsmono.

Снимки этапа 0: [iOS, светлая тема](docs/foundation/ios-light.png), [iOS, тёмная](docs/foundation/ios-dark.png), [Android, галерея в светлой теме](docs/foundation/android-gallery-light.png), [Android, тёмная](docs/foundation/android-gallery-dark.png). Галерея предназначена для проверки визуальных состояний. Элементы расписания и задач в ней демонстрационные.

Без debug-конфигурации отображается визуальный пример из `lib/main.dart`. Для связанного прототипа включите API-стенд по инструкции ниже: данные будут загружаться с сервера, а публикации — сохраняться после решения админа.

[Снимок экрана на Android-эмуляторе](docs/android-schedule-demo.png) показывает первый запущенный экран с учебными данными.

```bash
cd mobile
flutter pub get
flutter analyze
flutter test
flutter run -d <device-id>
```

Проверять на iOS Simulator и Android Emulator; список устройств — `flutter devices`. Первая Android-сборка может установить дополнительные компоненты SDK. Созданный Flutter package ID `ru.usity.usity` пока технический; перед публикацией приложения нужно закрепить окончательные идентификаторы и подписи.

## Связка с API и проверка ДЗ (учебный стенд)

В интеграционной ветке `codex/mobile-review-flow` доступны оба компонента:
backend из PR #18 и Flutter. При debug-конфигурации приложение получает с сервера
профиль, пары и ДЗ. Админ открывает очередь кнопкой проверки возле заголовка,
видит несколько исходных сообщений, редактирует текст, выбирает пару и публикует
или отклоняет. ДЗ появляется у пары; отметка выполнения скрывает его только
для текущей сессии. Есть переключение недель, обработка ошибок и повторная загрузка.

1. Подготовьте API по инструкции `../backend/README.md`:
   `USITY_DATABASE_URL`, `demo_review.py --prepare .env.demo-session`, Uvicorn.
2. Создайте локальный JSON `.env.flutter-demo` в корне репозитория с полями
   `USITY_API_URL` (`http://127.0.0.1:8000`) и `USITY_SESSION_TOKEN` (токен admin
   или student из `.env.demo-session`). Установите файлу права `600`.
3. Запустите Android-эмулятор. Настройте туннель:
   `~/Library/Android/sdk/platform-tools/adb reverse tcp:8000 tcp:8000`.
4. В папке `mobile` выполните:
   `flutter run --dart-define-from-file=../.env.flutter-demo`.

Файлы `.env.*` игнорируются Git. Ключи нельзя включать в коммиты, скриншоты,
презентацию или отправлять в чат. Учебные сессии живут 12 часов и могут попасть
в debug APK; такой APK не распространять. Release/profile не используют этот
способ входа. HTTP разрешен только для локальных адресов в клиенте; Android
cleartext включен только debug-манифестом.

Без конфигурации остается помеченный «Демо» визуальный пример. Это не email-вход.
Счётчик на вкладке «Настройки» в режиме API использует число ожидающих проверки черновиков группы из профиля admin/owner.
Синхронизация, offline, архив выполненных и push пока отсутствуют. Реальная LLM
не подключена: учебный backend создает черновик из фиксированного ответа.

Проверки: `flutter test`, `flutter analyze`.
Реальный Android-сценарий: открыть очередь → выбрать черновик → выбрать пару →
опубликовать → вернуться в расписание → отметить выполнение. Сервер проверяет
роль независимо от наличия кнопок. На iOS код пока не запускался.

Скриншоты живого Android-стенда:

- `docs/android-review-live.png` — исходные сообщения и редактор ДЗ;
- `docs/android-schedule-live.png` — опубликованное ДЗ, полученное через API.
