# Агент привязки ДЗ к расписанию

Владелец: Алексей Кочкин. Модуль запускается независимо от остальных агентов.
Он получает сообщения только из подключенной Telegram-темы, предметы группы и
опубликованное ручное расписание. Результат — предложение для очереди админа;
модуль не публикует и не изменяет ДЗ.

## Вход и результат

`bind_schedule(bundle, model, now)` принимает JSON-совместимый фрагмент
`EventBundle`. Обязательные поля: `group_id`, `chat_id`, `connected_chat_id`,
`topic_id`, `connected_topic_id`, `timezone`, `messages` (каждое с `id`,
`chat_id`, `topic_id`, `text`, необязательным `ocr_text`),
`semester` (`start`, `end`), `subjects` (`id`, `name`, `aliases`, `subgroups`),
`patterns` (`id`, `subject_id`, `weekday` от 0 для понедельника, `start_time`,
`parity`: `all`/`odd`/`even`, `subgroup_ids`). Необязательные `overrides`
описывают `cancel` или `move` для `pattern_id` и `original_date`; `extra_lessons`
содержат дополнительные занятия. Неделя 1 начинается в дату начала семестра.

Алиасы предметов и подгрупп задаёт админ/общий каталог группы. Включайте туда
употребляемые сокращения и неофициальные названия. Совпавший с несколькими
предметами алиас приводит к списку вариантов, без автоматического выбора.
Неизвестные формы остаются на проверке админа.

Результат содержит `subject_id`, `candidate_subject_ids`, `subgroup_ids`,
`lesson_id`, `candidate_lessons`, `uncertainty`, исходные сообщения,
`model_response`, `model_version` и `prompt_version`. Значение `null` означает
неизвестное поле; пустой список подгрупп означает весь предмет. `status=proposed`
означает лишь готовый черновик, который всё равно проверяет админ.

Общий backend должен передавать только данные подключенной темы и сохранять
полный `EventBundle`, ответ агента, последующие правки и решение админа с
ограниченным доступом. При интеграции ответственность за проверку роли админа,
конкурирующие решения и публикацию лежит в API, за пределами этого модуля.

## Запуск

Python 3.9+; сторонние Python-зависимости не требуются. Для реального вызова
модели установите `OPENAI_API_KEY` и `OPENAI_MODEL` в окружении и передайте
JSON-файл со входом на stdin (синтетический пример — `example_event.json`):

```bash
python3 -m backend.agents.schedule_binding < backend/agents/schedule_binding/example_event.json
```

Адаптер использует OpenAI Chat Completions со строгой JSON-схемой, согласно
[документации API](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create).
Другой провайдер может реализовать интерфейс `SemanticModel.extract`.
Поддержку схемы конкретной моделью и стоимость нужно проверить до эксплуатации.
Не помещайте ключ и реальные сообщения в Git.

## Проверка и оценка

```bash
python3 -m unittest discover -s backend/agents/schedule_binding/tests -v
python3 -m backend.agents.schedule_binding.evaluate
```

Первая команда проверяет правила и пограничные случаи без сети. Вторая запускает
реальную модель на шести синтетических примерах и считает верные предметы и
пары. Зафиксируйте вывод, версии модели и промпта перед демонстрацией. Этот
малый набор нужен для первого замера, а не для заявления о качестве в продукте:
до оценки на обезличенных размеченных сообщениях нельзя делать вывод о точности.
