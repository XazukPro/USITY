# Агент изменений и отмен ДЗ

Владелец: Дмитрий Дубенцев. Issue #8. Модуль запускается независимо от остальных
агентов. Он находит в сообщениях подключённой Telegram-темы исправление или
отмену уже опубликованного ДЗ и предлагает, какое задание затронуто. Агент
ничего не публикует и не меняет: результат — черновик для очереди админа.

## Вход

`detect_changes(bundle, model, now)` принимает `EventBundle` по проекту общего
контракта v0.1 (`docs/architecture/agent-contract-v0.md`, PR #16, Issue #1):
`schema_version="0.1"`, `event_id`, `group_id`, `messages` (`id` — строка,
`sent_at`, `text`, `attachments`; у фото `ocr_text`) и `context`:

- `active_assignments` — действующие ДЗ группы: `id`, `subject_id`, `text`, `due_at`;
- `subjects` — `id`, `name`, необязательные `aliases`, чтобы модель понимала «матан», «англ».

Проверку подключённой темы, сборку соседних сообщений и OCR выполняет общий
backend до вызова агента. `now` — время с часовым поясом; по нему определяется
«сегодня» для дат.

## Результат

`AgentRunResult`: `schema_version`, `event_id`, `agent_id="assignment_change"`,
`model_version`, `prompt_version`, `proposals` и `model_response` (сырой ответ
модели — вызывающий код хранит его отдельно от проверенного результата).
Пустой `proposals` означает «изменений нет». Сбой модели или неверный формат
ответа — исключение `AgentRunError` (с сырым ответом), а не пустой список.

Каждое предложение: `kind` (`assignment_update` или `assignment_cancel`),
`source_message_ids`, `uncertain`, `reason` и `fields`:

| Поле | Значение |
| --- | --- |
| `assignment_id` | затронутое ДЗ или `null`, если цель неоднозначна или не найдена |
| `candidate_assignment_ids` | все подходящие ДЗ из входа — варианты для админа |
| `new_text` | полный новый текст задания или `null` |
| `new_due` | `{"kind": "date", "date": "YYYY-MM-DD"}`, `{"kind": "next_lesson"}` или `null` |
| `evidence` | дословная цитата из сообщений |
| `review_flags` | причины проверки (см. ниже); `uncertain = true`, если список не пуст |

Привязку нового срока к конкретной паре делает агент расписания или админ.

## Что проверяет код, а не модель

- ID сообщений и ДЗ существуют во входе; ответ строго по схеме. Выдуманный ID
  сообщения делает весь ответ невалидным.
- `unknown_assignment`, `unknown_candidate_assignment` — модель назвала ДЗ,
  которого нет среди действующих; оно отбрасывается.
- `target_ambiguous`, `target_not_found` — цель не выбрана; варианты остаются админу.
- `evidence_not_in_source` — цитаты нет в исходных сообщениях или OCR.
- `cancel_with_new_values` — отмена с новым текстом/сроком; поля очищаются.
- `change_unspecified` — правка без нового текста и срока.
- `past_due_date` — новый срок уже прошёл.
- `model_uncertain` — модель сама отметила сомнение.

Сообщения Telegram — недоверенный ввод. Модель получает только сообщения,
предметы, действующие ДЗ и дату, без ID чатов и личных данных.

## Запуск

Python 3.9+; сторонние зависимости не нужны. Тесты работают без сети и ключей:

```bash
python3 -m unittest discover -s backend/agents/assignment_change/tests -t . -v
```

Реальный вызов GigaChat: скопируйте `.env.example` в `.env` (он в `.gitignore`),
заполните ключ и экспортируйте переменные, затем:

```bash
python3 -m backend.agents.assignment_change < backend/agents/assignment_change/example_event.json
python3 -m backend.agents.assignment_change.evaluate
```

`evaluate` прогоняет 12 синтетических примеров: правки текста и срока, отмены
(в том числе из двух сообщений), неоднозначную цель и сообщения, похожие на
правку, но ею не являющиеся (новое ДЗ, вопрос, напоминание, «уже сделал»,
попытка дать команду через чат). Считает найденные изменения, верный тип,
верное ДЗ и ложные срабатывания.

## Ограничения

- Адаптер GigaChat протестирован только с подменными ответами; работа
  `response_format` со схемой, лимиты и качество конкретной модели не
  проверены на реальном API. Адрес Chat Completions можно переопределить
  через `GIGACHAT_CHAT_URL`.
- Набор `evaluate` синтетический и маленький: это первый замер, а не качество
  на реальных чатах.
- Формат входа и выхода следует проекту контракта v0.1, который ещё не утверждён.
